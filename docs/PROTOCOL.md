# Remotes, DataStores and player attributes

Reference tables for the client-server protocol and the stored profile, moved out of AGENTS.md (2026-11-05) so they are read on demand.
AGENTS.md keeps the rules. Update this file in the same commit as any change to a remote, a profile field or a mirrored attribute.
Grep it for the remote, key or attribute you touch; don't read it whole.

## RemoteEvents
In `ReplicatedStorage`; the first three exist only in Studio (not in files), every other one is created at runtime by its service.

| Remote | Direction | Purpose |
|---|---|---|
| `StageTimerUpdate` | server → client | `(elapsed ≥ 0, stageKey)` run active; `(-1, final, result)` finished; `(-1)` cancelled |
| `StageTimerStopped` | — | unused since M0 (was the stop ack); can be deleted in Studio |
| `ResetPlayerTimer` | client → server | admin panel "Reset Score": full reset of the caller's own progress; server checks `AdminConfig` |
| `AdminAddCoins` | client → server, no arguments | admin panel "+Coins": server checks `AdminConfig`, credits `AdminConfig.AddCoinsAmount` to the caller; created at runtime by `AdminCoinsServer` |
| `CoinUpdateEvent` | server → client | created at runtime by `CoinSystem` |
| `CheckpointReached` | server → client `(part, first)` | created at runtime by `CheckpointTouchHandler`; the player's respawn point moved to that checkpoint (the stage's `TimerStart` counts as its first checkpoint) → `CheckpointClient` lights that pad and turns the previous one back, for that player only; `first` (first reach in the run) also plays the sound |
| `CheckpointsReset` | server → client, no arguments | created at runtime by `CheckpointTouchHandler`; a new run started (`NewRun`) → `CheckpointClient` turns every pad back |
| `GoHome` | client → server, no arguments | Home button; created at runtime by `HomeService`, 0.5 s cooldown, server teleports + cancels the timer |
| `GoGarden` | client → server, no arguments | the 🌱 Garden icon (top left, U2; not fired without a `GardenPlot` attribute); created at runtime by `HomeService` (own 0.5 s cooldown, independent of GoHome's), server teleports in front of the caller's plot (`GardenPlots.PlotOf`) facing it + cancels the timer |

| `LanguageRemotes.SystemLocale` | client → server `(localeId)`, once per join | the device's `LocalizationService.SystemLocaleId` (the server cannot read it); validated as a locale id, kept in the attribute `SystemLocale`; "automatic" = account `LocaleId` if supported and not English, else this (`Locale.Resolve`) |
| `TelemetryRemotes.Report` | client → server `("platform", kind)` / `("kill", part)` / `("fall")` | created at runtime by `Telemetry`; telemetry only, never trusted for gameplay; kill / fall rate-limited to 1 per s, the part must lie in a stage folder |
| `TalentRemotes.Buy` / `.Result` / `.Granted` | client → server `(talentId, expectedLevel)` / server → client `(talentId, ok, level or reason)` / server → client `(talentId, level)` | created at runtime by `TalentService`; the price and the crop bundle are never sent (EV2b: the level also takes `TalentConfig.crops[n]` from `Garden.Items`, with the Coins or not at all; too few crops → reason `crops`); a world-reward level (`TalentConfig` `rewards`, Double Jump with World 2) is refused (`reward`) and granted when the world opens, announced on `Granted` |

| `GardenRemotes.BuyCart` | client → server `(slot, cropId, count)` | created at runtime by `GardenField` (E1c4, the daily market cart); offers from `CropConfig.CartOffers(UTC day, Renown level)` (bargains on unlocked crops, a taste of the next locked crop from Renown 3), prices server-side; per-player counts in `Garden.Cart`, reset on a new day; accepted within 20 studs of the seed stall's counter (U4; else `far`); rejects `stale` (other offer, more than left) / `soldout` / `barn` / `coins`; answers on `GardenRemotes.Result` `("BuyCart", ok, { crop, count, price, taste? } or reason)`; Plant has no Renown gate (seeds held can be planted), BuySeeds keeps it |
| `GardenRemotes.FeedCrop` | client → server `(uid, cropId, count)` | created at runtime by `GardenField` (E1a3, crops as pet food, the pet's detail page); no plot distance; any owned pet; XP per crop from `CropConfig` `xp` (half the sale), care XP (P4, `PetConfig.GainCareXp`), the count clamped to what the pet can still use (`GardenConfig.XpToMax`; the last crop may go past it), the average size leaves `ItemSize`; rejects `items` (fewer held) / `maxed` (nothing left to train, nothing used), a bad uid / crop / count gets no answer; answers on `GardenRemotes.Result` `("FeedCrop", ok, { uid, crop, used, xp (used), level (pet level), trained = { { id, levels, level } } } or reason)` |

## Coins, mirrored attributes, runtime state
Gameplay Coins (medals, repeat rewards, pickups, future sources) go through `CoinRewards.Grant`; purchases and
deductions (and pet sales) call `PlayerProfile.AddCoins` directly. The multiplier is `PetService.Multiplier`
(1 + equipped pets' Cuteness bonus, capped at +50 %; a pet without Cuteness adds 0, P4). All Coin amounts were scaled ×10 in R2: records below `Version = 3` (and legacy
`PlayerCoins`) get `Coins × 10` once on load — never multiply stored Coins by hand. `RunsToday = { Day = <UTC day>, [stageKey] = medal finishes }` drives
the diminishing repeat reward (`StageConfig.RunReward`).

Player attributes `Medal_<stage folder>` (0–3) mirror `PlayerProfile.Medals` for client displays; `Unlocked_<stage folder>`
(bool) mirror `StageUnlocks` (bar met or `UnlockedStages[key]` bought; the bar is derived from medals, never stored).
`EquippedPets` (`"Kind:Level:uid,…"`, Level = pet level = the highest shown trait level, P4; empty when none; `PetConfig.DecodeEquipped` also reads the old `Kind:Level` form) mirrors the equipped pets; `PetFollow` renders them on every client.
`PetNames` (JSON `{ [uid] = filtered name }` of the named equipped and field pets, `""` when none; `PetConfig.DecodeNames`) carries pet names to every client (`PetFollow`, `GardenView` / `PlotView`); `EquippedPets` and the plot feed hold no names. The raw name is filtered again on every join.
A pet is either equipped or on a field square (E1b): `PetService` rejects Equip / SellPet of a field pet, `GardenService` / `GardenField` reject placing an equipped one.
Aptitudes (`PetConfig.Aptitudes`, E1b) are rolled once from `userId/uid` (at hatch, or by the `Version = 4` migration for pets from before E1b) and never rerolled; aptitude ids are stored: never rename one. `Cuteness` (P4) carries the Coin bonus (`PetConfig.PetBonus`); the migration gave every older pet Cuteness once at `1 + ceil((Level − 1) × 9 / 19)` (clamped to its cap). Tending works on the field (E1b), Scouting while equipped (E2c: medal finishes give it XP; the equipped scouts' `PetConfig.ScoutBonus` raises the rare-seed meter points and, at +50 %, the seed pouch).
A profile from before the field (P2 pens, no `Garden.Converted`) converts once on join: its pens become field pet slots (`CropConfig.PetSlotsFromPens`), penned pets rest, no refund (the slots are worth more than any pen set; FA: every player has the field); the Tending roll is deterministic per planting (`Squares[n].N`), a failed one marks it `Tried`.
Player attribute `GardenPlot` = slot of the borrowed plot (`GardenConfig.PlotCFrame(slot)`). The plots exist only on the clients (E1a1):
`GardenView` draws them into the client folder `Workspace.GardenView` (`Slot_NN` > pieces `base`, `inc1..3`, `field`, `sq1..36`) from
`GardenRemotes.Plot`; the server adds no instance to Workspace. Incubator countdowns come from `readyAt` (server time; display only).
Incubator eggs are stored with server `os.time()` only and checked at `Hatch`; to test hatching without waiting, move `StartedAt` / `ReadyAt`
back in the stored profile between playtests (snapshot and restore it).
`CollectedCoins` (sorted ids, comma-separated, `""` when none) mirrors `PlayerProfile.CollectedCoins[id] = true`;
`ChallengeCoinsClient` hides those coins for that player only (the server never hides a coin).

Checkpoint respawn state is kept in `ServerStorage.CheckpointData.<UserId>` (ObjectValue, runtime only).
