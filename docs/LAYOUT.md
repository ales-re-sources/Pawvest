# Code and scene layout

Reference map of `src/` and of the Studio-only scene, read on demand (AGENTS.md keeps the rules). Keep it current when a script is
added, renamed or changes its job. Function-level detail belongs in the code (file headers); per-stage as-built notes in STAGES.md.

## Adding a world stage
Clone the Studio-only templates `ServerStorage.StageKit.Gate` (door gate with its scripts), `StageKit.Top10Leaderboard` and `StageKit.Arrival` into the new stage folder, `PivotTo` / rotate them as a group onto a free gate position of the courtyard wall (the templates are laid out for a course running north from the gate line at z 187; the first checkpoint plate sits 7 studs behind the gate line), then add the `StageConfig` entry. Checkpoints: clone `ServerStorage.StageKit.Checkpoint` (plate + `Core` + `Beam` + the C Script; pivot = centre of the plate's top), rename it to the next free number and put its upstream edge against the previous obstacle, its front (LookVector, -Z) pointing along the course (the respawn faces that way). Scripts resolve the stage from the folder, so nothing else needs editing;
**Argon does not write the script files of instances created through the Studio MCP** (clones, `execute_luau`; changes to a synced script's `Source` made that way do not reach the disk either). For a new stage, copy the script directories from an existing stage on disk (`Gate`, `Top10Leaderboard`, `TeleportBackToStageStart`, one `<number>` per checkpoint; a plain directory is a Folder, the `init.meta.json` files hold the class), keep the old Studio folder, let Argon create the bare scripted instances from the copied files, then move the Studio-only children and the scripted parts' properties from the old folder into them (match by name; **children with duplicate names, like the three `Step` parts of a ChoiceStage, must be moved without matching**: a name match overwrites the first one), check that the descendant counts agree, and only then delete the old directories on disk. The templates' scripts are copies: when a stage script changes, change the template's copy too.
A cloned stage's gate sign (`Gate.Sign.Gui.Title`) keeps the source stage's literal text in the place file: set the Studio text of every new
stage's sign (the `GateSign` script writes the localized name at runtime; the literal is what Edit mode shows). Then add the stage to
`StageConfig`, give a course with a deep catch surface its `FallResetDepth`, and run the coplanar audit (AGENTS.md → Gotchas).
